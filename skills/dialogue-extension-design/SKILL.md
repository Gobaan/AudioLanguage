# Dialogue Extension Design

## Purpose

Use this skill to grow a familiar anchor scene carefully. Extensions should deepen capability without turning the scene into a long memorized script.

## Core Rule

Add one meaningful new burden at a time.

Good extension:

```text
Friend: Fine. Thank you. And you?
Learner: I'm fine.
```

Bad extension:

```text
Adds five new turns, three new functions, and several new grammar points.
```

## When To Extend

Extend only when the current target is stable enough.

Suggested gate:

- Success on 2 different days.
- At least one success from visual-only support.
- At least one transfer scene success.
- Response latency is acceptable.
- Current review load is not overloaded.

If the user returns after a long break, recalibrate before extending.

## Extension Types

Use one extension type at a time:

- **Ask-back**: add "And you?"
- **Answer-back**: add "I'm fine."
- **Slot expansion**: add one replaceable word or phrase.
- **Repair**: add "Can you say it slowly?"
- **Emotion**: add tired, happy, busy, worried.
- **Next action**: add "See you later" or "Come in."

## Freeze, Split, Or Branch

Do not extend forever.

Beginner scene length guide:

- 3 turns: first exposure.
- 4-6 turns: useful anchor.
- 6-8 turns: maximum.

When the scene wants to teach a second communicative job, split it.

Example:

```text
Scene A: Greeting
Scene B: What are you doing?
Scene C: What are you studying?
```

They may share characters, room, and story continuity, but they should be separate practice units.

## Layered Memory

Treat each new line or function as its own layer.

```text
Layer 0: Hello
Layer 1: Hello! How are you?
Layer 2: I'm fine
Layer 3: I'm studying
```

Old layers should become warm-up or maintenance targets. New layers get shorter intervals and more support.

## Long-Break Rule

After a long break:

- Do not continue extending automatically.
- Test the strongest prior layer first.
- If rusty, recover the anchor before adding anything.
- If stable, resume extension.

## Output Format

When extending a dialogue, output:

- Existing anchor summary
- Current stable target
- Proposed new layer
- Why this is the next smallest useful move
- Revised dialogue
- What remains unchanged
- New target response contract
- Review schedule impact
- Split/freeze warning if scene is getting too long

## Quality Checklist

- Does the extension add exactly one new conversational move?
- Does the old target remain retrievable?
- Is the new line visually and socially motivated?
- Is the scene still short?
- Would this be better as a sibling scene?
- Are old and new memory targets tracked separately?
